## 原因与处理

启动查找顺序原本已经是 config.yaml、config/config.yaml、config/manifest/config.yaml，但 worker 会固定启动时选中的文件。用户在运行中移走原配置后，安装器仍沿原位置读写，重启执行器则选根 YAML，导致配置来源和有效数据库不一致，自动交接被拒绝。旧 worker 在切换前读取安装会话时还可能访问原数据库；界面会将过渡期失败显示为交接会话失效。

配置服务增加不改变启动快照的文件发现入口。安装检查、数据库保存、交接参数及来源摘要统一使用最新选择；原子保存继续检查配置身份、互斥、权限和提交前的文件优先级变化。根文件无效不回退，非数据库参数保留，内置 YAML 保持只读。普通运行时文件选择和数据库连接继续在重启前固定。

旧 master 的 scheduled/restarting 交接查询返回 503 和 Retry-After，页面对服务端暂不可用继续轮询；没有安装身份的请求、错误 CSRF 及已失效首次登录资格继续拒绝。
