# 企业官网安全边界与部署

2026-11-09。本轮以企业展示官网为目标，保留栏目、文章、产品、广告、附件、搜索、留言、多语言、SEO、静态生成和普通模板文本管理。已完成的 3144 SQL 导入修复不变。具体测试、现存缺页和发布情况见 [验收记录](security-hardening-acceptance.md)。本说明覆盖旧文档中关于插件、可视化和在线 PHP 生成的描述。

## 已关闭的能力

EyouCMS 业务插件与 Webman 在线插件的安装、更新、卸载、调用、路由、配置、命令扫描和钩子执行不再提供。历史数据库记录保留，不能激活代码。Composer 包事件不再调用第三方安装器，应用内配置由源码维护。Composer 锁定依赖、`plugin\admin\` 后台身份、权限节点和连接别名保留。

可视化编辑、保存、上传和工具脚本停止提供，`uiset=on` 不开启编辑模式。主题预检对可视化内容、插件数据标签报告文件与行号；纯 `{eyou:ui}` 编辑器挂载和无内容的默认插件挂载输出空。旧会员和支付模板含 PHP 时单页拒绝，不因此禁止 3144 企业主题的普通页面。

Web 在线生成 PHP 代码关闭。普通文件管理只允许当前授权主题内的 HTM、JS、CSS、TXT 文本；模板图片上传替换关闭。已有图片可继续读取。模板保存采用内容哈希检查和原子发布，拒绝符号链接、硬链接、路径越界和 PHP 开始标记。

## 查询、文件与模板

搜索、筛选、自定义字段和相关文章值采用参数绑定；标识符和排序采用服务端字段范围及受限语法。`{eyou:sql}` 仅接受完整匹配的静态单表 SELECT 子集：展示表白名单、字面量条件、字段排序和数字 LIMIT。拒绝动态 SQL、多语句、注释、函数、子查询、UNION、文件操作和非展示表。旧广告、FAQ 自定义 SQL 条件不再执行。原始 Query API 仍是内部开发接口，不代表任何请求字符串都可以安全传入。

新上传先进入系统临时目录内的任务私有暂存；校验大小、名称、扩展名、MIME、实际图像/文件结构后，以随机文件名独占发布到 `public/uploads`。请求中的目录参数不能改变目标。PHP、PHAR、服务器配置文件、双扩展名、伪造图片、Office 宏及不支持的压缩包被拒绝。失败只清理本任务文件。旧附件配置不能重新启用被禁止的格式。图片内随机 PHP 相似字节不能单独作为木马结论。

前台保存、渲染、预览及静态生成复用模板源策略；include、继承、布局复用文件边界。包含文件限制在所选主题内，拒绝链接和越界。表达式使用 AST 白名单；编译结果再次检查 AST，只允许固定内部标签、受限辅助函数及必要集合操作。普通字段的 PHP 反序列化禁止构造对象，签名集合缓存只开放固定内部类。标签库仅为内置 Eyou/Cx；禁止原生 PHP、任意函数/方法、动态类和动态标签库。编译器的可信兼容重写只发生在安全检查之后；本轮未新增 eval。

## runtime 与密钥

启动必须配置 `CMS_SECURITY_KEY_FILE`。使用项目外规范绝对路径，指向普通、单链接的私有文件；内容是随机 32 字节密钥的 64 位小写十六进制。密钥及父目录不能被组或其他用户写入。密钥缺失、格式无效或权限异常时明确失败，不接受未签名缓存。

先由部署账号创建私有目录，再运行（PHP 8.2 或更新版本）：

```sh
php app/cms/maintenance/security-key.php --create=/etc/cms-private/site.key
php app/cms/maintenance/security-key.php --check=/etc/cms-private/site.key
```

将 `CMS_SECURITY_KEY_FILE` 通过私有配置或显式进程环境指向该文件。禁止把密钥写入源码、runtime、上传目录、版本库或公开安装包。多个 worker 共用同一密钥；不同站点使用不同密钥。密钥在进程内缓存，轮换后必须重启全部 worker，旧会话需重新登录。

前后台模板、数据缓存、语言资源和会话使用不同 HMAC 用途，认证完整原始头部和正文后才解析元数据、反序列化或执行。站点部署身份包含项目路径与数据库连接身份；模板和数据缓存额外绑定模式、站点签名、版本、缓存标识和有效期。会话绑定 ID、协议版本和有效期。仅空状态或符合固定名称及十六进制长度的三个安装交接字段使用独立匿名用途，以便安装时切换数据库；包括旧 admin_id、admin_info、users_id 在内的其他状态一律绑定数据库及安装模式。启动时拒绝 Webman 的 igbinary 会话配置，要求默认 PHP 序列化。管理员还必须通过数据库内的会话注册/撤销记录，防止回放已退出的有效旧会话。

前台认证包含依赖元数据及编译正文。后台关闭 vendor 的旧缓存复用，始终从可信后台源重新编译，使用自有签名存储；未修改 vendor 实现。模板执行只读取内部只读流保存的已验证内存快照，验证后磁盘文件被替换也不会改变执行字节。语言派生 JS 同样从已验证内存返回。篡改缓存拒绝并重建；篡改会话拒绝并重新登录。runtime 保持可重建，数据库中的有效业务状态保留。

## 主机权限与代理

生产部署使用独立部署账号和服务账号。建议权限如下；应由主机部署配置应用，不能把开发机同一用户启动的测试当作操作系统隔离验收。

| 位置 | 部署账号 | 服务账号 |
| --- | --- | --- |
| app、vendor、support、入口和配置 | 管理/发布 | 只读 |
| 项目外密钥及私有父目录 | 管理 | 只读/可遍历，无创建、改名或删除权限 |
| runtime | 无需保存业务状态 | 可写、可重建 |
| public/uploads、public/html | 按业务备份 | 受控写入 |
| 授权主题范围 | 发布/备份 | 仅业务明确开放的普通文本管理范围 |
| 其他主题、原 SQL、安装封存 | 管理 | 只读或不可访问 |

保留在线模板编辑需要开放明确主题目录的写权限。安装阶段仅固定数据库受管块需要写入源码配置；安装完成后撤销服务账号对该文件及其父目录的写权限，后续配置变更由受信部署账号维护。不要使源码或密钥父目录归服务账号所有。PHP 路径 API 不能提供与系统 openat/no-follow 完全相同的目录竞争保证；最小目录权限是路径检查的必要部署配套。

提供 [Webman 专用 Nginx 示例](../app/cms/resources/deployment/security-nginx.conf)：所有响应经 Webman，私有目录及危险文件拒绝；不接 PHP-FPM、不用 try_files 绕过受管 HTML 校验。替换域名、TLS 和监听后再纳入正式虚拟主机。本轮不修改原 EyouCMS 虚拟主机。

## 事件与回退

怀疑入侵时先保全日志、文件摘要和数据库证据，不自动删除或隔离。单次静态特征扫描不能证明没有木马。此轮防护针对恶意 HTTP 请求和仅能修改 runtime 的攻击者；控制服务进程、部署账号、密钥或系统管理员的情况需要主机处置。

发布前对每个变更文件单独备份，记录原 SHA；保留原 SQL、主题、附件、业务数据及 Git 暂存。不要把隔离库、测试账号、候选 `.env` 或 runtime 复制到运行站。回退须先停止目标站全部 worker，逐文件恢复本次备份和原私有配置（包括 `config/database.php` 与可能存在的 `.env`），重新生成 Composer autoload，再启动；不把整份旧 runtime 覆盖到运行进程。恢复旧版本会重新暴露本轮已关闭的执行入口，故应仅作紧急回退并限制访问。
