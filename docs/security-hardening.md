# 企业官网安全边界与部署

2026-11-09。本轮以企业展示官网为目标，保留栏目、文章、产品、广告、附件、搜索、留言、多语言、SEO、静态生成和普通模板文本管理。已完成的 3144 SQL 导入修复不变。具体测试、现存缺页和发布情况见 [验收记录](security-hardening-acceptance.md)。本说明覆盖旧文档中关于插件、可视化和在线 PHP 生成的描述。

## 已关闭的能力

EyouCMS 业务插件与 Webman 在线插件的安装、更新、卸载、调用、路由、配置、命令扫描和钩子执行不再提供。历史数据库记录保留，不能激活代码。Composer 包事件不再调用第三方安装器，应用内配置由源码维护。Composer 锁定依赖、`plugin\admin\` 后台身份、权限节点和连接别名保留。

可视化编辑、保存、上传和工具脚本停止提供，`uiset=on` 不开启编辑模式。主题预检对可视化内容、插件数据标签报告文件与行号；纯 `{eyou:ui}` 编辑器挂载和无内容的默认插件挂载输出空。旧会员和支付模板含 PHP 时单页拒绝，不因此禁止 3144 企业主题的普通页面。

Web 在线生成 PHP 代码关闭。普通文件管理只允许当前授权主题内的 HTM、JS、CSS、TXT 文本；模板图片上传替换关闭。已有图片可继续读取。模板保存采用内容哈希检查和原子发布，拒绝符号链接、硬链接、路径越界和 PHP 开始标记。

## 查询、文件与模板

搜索、筛选、自定义字段和相关文章值采用参数绑定；标识符和排序采用服务端字段范围及受限语法。`{eyou:sql}` 仅接受完整匹配的静态单表 SELECT 子集：展示表白名单、字面量条件、字段排序和数字 LIMIT。拒绝动态 SQL、多语句、注释、函数、子查询、UNION、文件操作和非展示表。旧广告、FAQ 自定义 SQL 条件不再执行。原始 Query API 仍是内部开发接口，不代表任何请求字符串都可以安全传入。

新上传先进入系统临时目录内的任务私有暂存；校验大小、名称、扩展名、MIME、实际图像/文件结构后，以随机文件名独占发布到 `public/uploads`。请求中的目录参数不能改变目标。PHP、PHAR、服务器配置文件、双扩展名、伪造图片、Office 宏及不支持的压缩包被拒绝。失败只清理本任务文件。旧附件配置不能重新启用被禁止的格式。图片内随机 PHP 相似字节不能单独作为木马结论。

前台保存、渲染、预览及静态生成复用模板源策略；include、继承、布局复用文件边界。包含文件限制在所选主题内，拒绝链接和越界。表达式使用 AST 白名单；编译结果再次检查 AST，只允许固定内部标签、受限辅助函数及必要集合操作。普通字段的 PHP 反序列化禁止构造对象，集合缓存只开放固定内部类。标签库仅为内置 Eyou/Cx；禁止原生 PHP、任意函数/方法、动态类和动态标签库。编译器的可信兼容重写只发生在安全检查之后；本轮未新增 eval。

## runtime、缓存与会话

程序不创建或读取本地签名密钥；源码、二进制构建、安装、缓存及数据库备份均无需 key 文件。旧 `security.key_file` 和 `CMS_SECURITY_KEY_FILE` 仅用于给出废弃提示，不参与运行。不使用硬编码或自动生成的替代密钥。

缓存使用独立 storage-v2 协议，与旧签名缓存隔离。前台编译缓存读取时校验记录格式、过期时间、依赖路径及 SHA，再检查编译正文 AST；元数据只能是固定格式的 JSON/Base64 注释，不能携带可执行 PHP。运营与 Redis 模式都复用依赖未变的编译结果，开发模式每次编译。后台始终从可信应用模板重新编译，只执行本次生成的内存快照；不执行磁盘缓存文件。

数据缓存反序列化仍限制内部类和递归深度。语言字典与数据库解析结果对照，动态语言 JS 使用本次生成的请求内字节。分页在原字段保存版本化查询描述，通过固定标签查询构造器重算总数，不执行数据库保存的 SQL；旧记录刷新页面后重建。

会话沿用 Webman 的 Cookie、随机 ID、序列化与 TTL，存储使用 session-v2 命名空间，一次性使本次升级前的会话失效。文件会话绑定部署、数据库与会话代际，Redis 会话保持原故障503及切换失效规则。只有三个固定名称、固定长度的安装交接字段能使用站点根绑定的匿名存储，以便安装切换数据库；该存储拒绝任何身份字段。拒绝对象反序列化及 igbinary 配置。管理员登录仍须通过数据库的注册、撤销及随机 nonce 校验，退出后旧会话不能重新取得权限。

取消 HMAC 后，摘要用于格式、依赖和意外损坏检查，不提供抗伪造认证。私有文件和本站 Redis 的写权限是存储信任边界，必须由可信运行账号控制；可写存储不应向外部用户开放。模板 AST 校验和后台强制编译继续限制缓存中的可执行能力，不能把它们等同于存储内容真实性认证。
## 主机权限与代理

生产部署使用独立部署账号和服务账号。建议权限如下；应由主机部署配置应用，不能把开发机同一用户启动的测试当作操作系统隔离验收。

| 位置 | 部署账号 | 服务账号 |
| --- | --- | --- |
| app、vendor、support、入口和配置 | 管理/发布 | 只读 |
| runtime | 无需保存业务状态 | 可写、可重建 |
| uploads、public/html | 按业务备份 | 受控写入 |
| 授权主题范围 | 发布/备份 | 仅业务明确开放的普通文本管理范围 |
| 其他主题、原 SQL、安装封存 | 管理 | 只读或不可访问 |

保留在线模板编辑需要开放明确主题目录的写权限。安装阶段仅固定数据库受管块需要写入源码配置；安装完成后撤销服务账号对该文件及其父目录的写权限，后续配置变更由受信部署账号维护。不要使源码父目录归服务账号所有。PHP 路径 API 不能提供与系统 openat/no-follow 完全相同的目录竞争保证；最小目录权限是路径检查的必要部署配套。

二进制启动前自动整理所选外置配置、私有状态、上传、生成 HTML 和外置资源的权限，源码启动不自动处理；具体范围及 `cms:permissions --check|--fix` 见 [构建与启动](../BUILD.md)。不更改所有者，不跟随链接，不修改包内资源，不将同一种权限递归应用于整个站点。YAML 的读取规则禁止其他用户权限，`600` 是新配置默认值，已有可读的 `400/640/660` 也允许。自动修复保留这些有效配置权限；运行账号无权修改或文件系统只读时明确失败。

若 Nginx 与 CMS 同属 `www`，即使配置为 `600`，Nginx 仍能读取。必须通过虚拟主机规则阻止配置下载，权限整理不会修改 Nginx，也不能替代公开访问授权。

提供 [Webman 专用 Nginx 示例](../app/cms/resources/deployment/security-nginx.conf)：所有响应经 Webman，私有目录及危险文件拒绝；不接 PHP-FPM、不用 try_files 绕过受管 HTML 校验。替换域名、TLS 和监听后再纳入正式虚拟主机。本轮不修改原 EyouCMS 虚拟主机。

## 事件与回退

怀疑入侵时先保全日志、文件摘要和数据库证据，不自动删除或隔离。单次静态特征扫描不能证明没有木马。存储信任边界见上文；控制服务进程、私有存储、部署账号或系统管理员的情况需要主机处置。

发布前对每个变更文件单独备份，记录原 SHA；保留原 SQL、主题、附件、业务数据及 Git 暂存。不要把隔离库、测试账号、候选 `.env` 或 runtime 复制到运行站。回退须先停止目标站全部 worker，逐文件恢复本次备份和原私有配置（包括 `config/database.php` 与可能存在的 `.env`），重新生成 Composer autoload，再启动；不把整份旧 runtime 覆盖到运行进程。恢复旧版本会重新暴露本轮已关闭的执行入口，故应仅作紧急回退并限制访问。
