# 二进制启动权限整理验收

日期：2026-11-11。

本次增加二进制启动前权限准备及 `cms:permissions` 命令。只检查命令默认不修改，`--fix` 显式修复。自动准备在配置读取和 Workerman 处理 `-d` / `restart` 前执行；后台重启在新进程处理下一次启动的配置，再执行原有部署预检。权限失败或资源失败时保留旧主进程。

## 验证环境与证据

所有测试数据位于项目外 `/private/tmp/cms-permissions-20261111-104207`。`before/` 保存原文件前镜像，`acceptance.php`、`results.json` 保存 macOS ARM64 PHP/PHAR 隔离验收；`linux-fixture.php`、`linux-check.sh`、`linux-results.txt` 保存 Linux 检查。测试 PHAR 只包含所需入口及类，使用隔离文件夹具，不连接业务数据库，不属于完整 CMS 成品。临时夹具与合成二进制验证后清理，保留脚本、结果及前镜像。

Linux 检查使用已有锁定 Linux x86_64 micro 运行时与测试 PHAR 合并，在本机 ARM64 Docker 中通过 amd64 仿真执行，容器关闭网络、以 UID 1000 执行权限操作。原生 Linux 服务器及完整成品启停未在本次执行，不将仿真结果算作原生平台验收。

## 已通过

- 外置 YAML `644` 自动收紧为 `640`；已有 `400/600/640/660` 保持有效权限，内容 SHA 和所有者不变。
- `--check` 和原有部署预检不修改配置、不创建受管数据目录；有效模式但运行账号不可读时也报错；`--check --fix` 冲突拒绝。
- 所有者可修复 `555` 发布根及父目录、不可遍历的私有配置目录、不可读 `.env`；先读取有效 env，再修复其选中的 YAML。未选中的候选 YAML 不改动。已有 HTML 时也检查 public 父目录，不遗留其他用户写入位。
- 重复修复返回零调整；创建必要 `config/runtime/uploads/public/html`，不创建 `install`、`runtime/cms`、`runtime/views`、文件会话目录，不连接 Redis。
- 已有只读主题和系统资源保留只读；内置根及内置 YAML 忽略的外置副本不参与修复，即使这些副本包含无效内容或链接。
- 符号链接、硬链接拒绝，外部目标权限不变；以 UID 1000 修改 root 所有的 `644` YAML 明确失败。root 所有、组 1000 可读的 `640` YAML 可通过。
- `start -d`、`restart -d`、容器入口在读取配置前整理权限；缺 YAML/主题时终端与 `bootstrap.log` 均给出错误，退出非零，不产生 worker PID，不创建空资源目录。
- 失败的重启准备保留已有 PID 文件；`status/stop/reload/connections` 不触发自动权限修复（入口原有错误日志行为保留）。
- 改动 PHP 文件通过语法检查，源码命令帮助可用；Git 暂存摘要保持不变。

本次没有修改运行站权限、私有配置、数据库、上传、会话、当前主题或模式，没有重启现有 worker，没有连接用户 Redis 或操作 8793。没有替换服务器二进制或 Nginx。功能随下一次源码构建进入成品。

## 边界

只有文件所有者或具备操作系统权限的账号可以 chmod；程序不 chown、不提升权限、不安装工具。只读挂载、ACL、不可变标记等限制由部署者处理。二进制缺执行位时无法先运行自修复。Nginx 与 CMS 同账号时，必须靠虚拟主机访问规则保护 YAML，不能依赖 `600` 阻止下载。

未执行本轮完整数据库启动、HTTP/浏览器、真实 systemd 后台重启、全部缓存模式业务回归或原生 Linux 服务器验收。已有只读资源保持行为已验证；实际只读挂载的失败路径另外使用 Docker 只读挂载检查。
