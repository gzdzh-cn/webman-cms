# 本地语言包与翻译维护

多语言总开关位于功能地图的搜索下方、当前导航上方。编辑语言统一在后台右上角选择。本地语言包从“站点设置 → 多语言 → 功能配置”进入，页面不另设编辑语言切换器。

## 文件格式

只接受 UTF-8 JSON，不读取或执行上传 PHP；单文件不超过 2 MiB、最多 5000 项。对象重复键（包含 Unicode 转义后的同名键）和重复变量名均拒绝。

```json
{
  "format": 1,
  "language": "en",
  "entries": [
    {"name": "sys1", "value": "Home"},
    {"name": "contact_title", "value": "Contact us"},
    {"name": "optional_note", "value": ""}
  ]
}
```

`language` 必须与当前编辑语言一致。变量名沿用 1～50 位字母、数字、下划线和连接符的既有规则，大小写归一。变量值必须为字符串，单项最多 65535 字节。空字符串是有效的实际译文，不会被主语言回退覆盖。

## 导入、编辑与导出

导入先预览新增、相同及冲突项。确认令牌绑定文件 SHA、目标语言、当前变量修订、站点模板模式、站点签名及操作者，15 分钟后失效。文件或数据变化需重新预览。批量导入只插入数据库缺失项；同名现有值全部保留，不提供批量强制覆盖。相同令牌重复确认返回已完成结果，不重复插入。

要修改已有译文，使用变量行的编辑操作。未提供的语言不创建空值。基础变量名不能修改，保留原有系统变量保护。删除自定义变量仍是删除其全部语言值，需要具备全部受影响语言权限。

导出 `entries` 只包含实际值（数据库或对应语言本地基础值）。主语言回退另列为 `pending`：

```json
{
  "name": "missing_title",
  "status": "pending",
  "fallback": "主语言文字"
}
```

`pending` 中的内容不会作为实际译文导入，不能直接将带 `pending: true` 的回退条目放入 `entries`。超过文件限制的词库需按变量范围在维护流程中拆分，不返回无法再次导入的超限文件。

## 值来源与待翻译

解析顺序为目标语言数据库值、目标语言本地基础值、系统主语言数据库值、系统主语言本地基础值。只有使用后两者回退时标记待翻译。没有任何定义和值时标记未定义。历史数据库值不会因与主语言相同就被推断为未翻译。

“补齐缺失变量”补定义及待译记录，不把主语言回退文案写入 `language_pack` 假装译文；不复制或修改文章。内容同步和语言包维护是两个独立操作。

## 私有基础包和缓存

可信基础包在 `app/cms/resources/languages/<语言>.json`，包含 `format`、`language`、`core`、`template`。已有可信 PHP 词典经过定点转换为 JSON，运行时不执行这些 PHP。原兼容 `Lang::load` 对冻结旧路径读取转换结果，其余仅接受 JSON。

数据库保存人工实际值，`cms_state_records` 保存变量定义、翻译来源、预检及幂等记录。解析缓存位于 `runtime/cms/languages`，按站点签名、模板模式、语言及值摘要隔离，可删除并自动重建。删除缓存不会删除译文、变量或预检记录。

`LanguageDictionary::revision($language)` 提供单语言词库修订，`aggregateRevision()` 提供全语言聚合修订（包含停用语言）。静态页面、Sitemap及其他派生任务使用该签名隔离词库变化；这两个接口只读，不触发后台编辑语言、会话或权限范围变化。

外贸助手仍使用独立的 `foreign_pack` 词库。其默认源语言来自系统主语言，英文模式保留既有协议；生成 JS 从数据库派生到 `runtime/cache/assets`，旧公开 URL 由精确资源映射兼容，不再改写主题或共享资源实体。值使用 JSON 编码写入 JS，删除 runtime 后重新生成。

## 官方联网功能退出

后台不再提供检查官方更新、获取官方包或同步全部语言包。旧动作及退役客户端均明确返回“官方语言包联网功能已停用”，没有 HTTP 请求。安装、后台维护和冷缓存重建均无需语言包网络服务。
