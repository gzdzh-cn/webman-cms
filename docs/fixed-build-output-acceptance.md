# 固定平台构建目录验收

日期：2026-11-11。

构建目录改为 `cms-<平台>`，例如 `bin/cms-linux-x86_64/cms`。重复构建自动整体替换对应平台目录，旧文件不会混入新产物。版本号及输入摘要仍保存在 `release.json` 和二进制内。未参与本批的平台、运行时缓存、历史带版本号目录保持原状。

所有目标构建完成后，通过输出根下 `.cms-publish.lock` 串行发布。旧目录先移入本批暂存目录；发布失败恢复旧目录，成功后清理暂存。恢复遇到文件系统阻碍时保留并提示旧产物备份位置。运行时缓存不能设在将被替换的平台目录内，缓存与输出共用父目录仍允许。

## 实际验证

- PHP 语法和差异格式检查通过，Git 暂存摘要不变。
- 隔离发布验证：首次发布、重复覆盖、清理旧文件、其他平台/缓存保留、多平台中途失败恢复、非法目标和链接拒绝、恢复失败保留备份，以及两个发布进程的互斥。
- 隔离完整 CLI 构建：两种 Linux 平台固定目录、二进制摘要、重复构建替换、内部版本保留、进度写 STDERR、暂存清理，以及后一个平台运行时失败时旧产物保持不变。
- 补充验证：运行时位于平台目录内明确拒绝；缓存与输出共用父目录时正常构建、缓存不丢失。

完整 CLI 验证使用合成 ELF 头及隔离副本中的匹配摘要，不执行合成二进制，仅验证打包与发布流程，不作为原生平台启动验收。

证据及前镜像位于 `/private/tmp/cms-fixed-release-20261111-111129`，包括发布、CLI、运行时路径验证脚本及结果。合成成品和测试副本完成后清理，保留日志及前镜像。

没有重新构建运行站成品、修改私有配置、数据、主题或缓存模式，没有重启 worker，没有操作 8793 或用户 Redis。新目录行为从下一次构建生效。
