# 安装中断后自增计数恢复验收

日期：2026-11-09，Asia/Shanghai。实施对象为 Webman CMS；开发站仅8787，8793及原EyouCMS不变。发布状态见文末。

## 原因与修复范围

MySQL5.7重启可能将InnoDB下一自增值重算为现有最大ID加一。安装检查点原本将这个值计入完整SHOW CREATE TABLE摘要，因此即使结构其它部分和全部行字节一致，也会拒绝续装。

仅修改当前FORMAT3的InstallerService，新增InstallerTableIdentity；冻结的InstallerLegacyV2保持原SHA。新检查点额外记录实际自增值的十进制字符串，支持无符号BIGINT，不经过PHP整数或浮点转换。既有完整结构、行数、排序后行数据摘要均不放宽。

在已有文件锁和数据库安装锁内，只有本任务的暂存表或已重命名目标表、阶段及发布拓扑符合、行数和数据摘要完全一致、引擎为InnoDB、且下一自增值严格下降时才考虑恢复。将旧值代回实际DDL必须精确还原原完整schema SHA。旧三字段检查点只尝试可信源CREATE明确声明的值；不能证明原值的旧任务继续拒绝，不能猜测或改写检查点。

恢复先保存planned意图，再执行单条ALTER提高计数，重读完整指纹后记complete；ALTER完成但收据未落盘可核验原意图后补收据。意图绑定任务、物理表、源CREATE、原检查点及目标schema。quoted文字、SQL注释不参与选项识别；未闭合块注释拒绝。不会降低计数、删除重导已校验数据或放行其它结构差异。冲突原表仍使用原严格metadata，计数变化也会阻止删除。

## 使用与回退

中断时保留标准install、私有config/cms-installing.json及任务表，按原安装参数继续；不得清理journal、暂存表、手改SHA或降低计数。恢复记录在journal.counter_repairs，不依赖runtime。数据或结构变化、旧计数不可证明时仍应停下人工核对。

不参与安装锁的外部SQL writer须停写，本功能不能防止任意外部并发写。它只处理能证明的InnoDB计数下降，不能解决所有数据库崩溃或导入失败。T16总体、T17、HTTP大库容量及全部角色异常组合继续留项。

发布前保存明确文件清单及项目外原文件备份。回退先停8787全部worker，只恢复本批代码/文档；不恢复整库、.env、安装记录、主题、上传或生成HTML，不删除用户新数据。曾采用新计数恢复的未完成任务回退旧代码后可能再次被旧校验拒绝，应保留journal，避免盲目反复回退。
